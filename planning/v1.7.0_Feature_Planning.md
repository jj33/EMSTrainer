## 🎯 Core Philosophy - Multi-Level Support (NON-NEGOTIABLE)

**CRITICAL:** All v1.7.0 features MUST support multiple certification levels.

**Primary Target Audience:**
1. **EMT** (Emergency Medical Technician) - Priority 1
2. **Paramedic** - Priority 1
3. **EMR** (Emergency Medical Responder / First Responder) - Priority 2

**Future Expansion:**
4. Critical Care Paramedic (CCP) - Tier 3
5. Air Care Paramedic (ACP) - Tier 3

**Every Feature Must Answer:**
- ✅ Can EMR students use this feature effectively?
- ✅ Can EMT students use this feature effectively?
- ✅ Can Paramedic students use this feature effectively?
- ✅ Does grading scale appropriately per cert level?
- ✅ Do scenarios work across all levels?

**If any answer is "no":** Adapt the feature or don't build it.

**See:** [Project Philosophy](../docs/PROJECT_PHILOSOPHY.md) for complete multi-level support guidelines.

## 🎯 Release Goals

v1.7.0 focuses on **instructor workflow enhancements** and **continued realism** while maintaining the chat-based simplicity that makes EMSTrainer accessible **across all certification levels**.

### Core Themes:
1. **Protocol Integration** - Validate scenarios against local medical director protocols
2. **Timing Customization** - Flexible timing standards for different environments
3. **Equipment Realism** - Add timing delays and setup requirements
4. **Instructor Tools** - Enhanced scenario creation and management
5. **Multi-Agency Dynamics** - Fire, Police, First Responder integration

### Priority Shift from Previous Planning:
- **NEW Priority 1:** Protocol Loading & Validation (user HIGH PRIORITY request)
- **NEW Priority 1:** Timing File Generator (designed and ready)
- **MOVED to Priority 2:** Equipment timing delays
- **MOVED to Priority 2:** Multi-agency dynamics
- **DEFERRED to v1.8:** Encryption features (complexity vs value)

## 🚀 Priority 1 Features (Must-Have)

### 1. Protocol Loading & Validation ⭐ HIGH PRIORITY

**Status:** User Requested - Top Priority  
**Description:** Upload local medical director protocols and validate scenarios against them.

**Purpose:**
- Ensure training scenarios match current agency protocols
- Identify protocol updates requiring scenario revisions
- Quality assurance for instructor-created content
- Accreditation/documentation compliance

**Implementation:**

**Phase 1: Protocol Upload**
```
Instructor: [uploads protocol PDF or text]
AI: "Analyzing protocol document...

Found protocols for:
- Cardiac arrest (8 pages)
- Symptomatic bradycardia (3 pages)  
- Anaphylaxis (2 pages)
- STEMI (4 pages)
- Trauma (12 pages)

Protocol reference loaded. Ready to validate scenarios."
```

**Phase 2: Scenario Validation**
```
Instructor: [loads scenario] "Validate against protocols"

AI: "Validating cardiac_arrest_vf.json against protocols...

✅ COMPLIANT:
- Epi dosing: 1mg IV/IO q3-5min (matches protocol)
- Defib energy: 200J biphasic (matches protocol)
- CPR ratio: 30:2 (matches protocol)

⚠️ POTENTIAL ISSUES:
- Scenario allows 15min for 12-lead
- Protocol requires 10min for STEMI recognition
- Recommendation: Adjust scenario timing window

❌ CONFLICTS:
- Scenario includes amiodarone 300mg
- Protocol specifies amiodarone 150mg first dose
- MUST FIX before deployment

Generate corrected scenario?"
```

**Phase 3: Protocol-Compliant Scenario Generation**
```
Instructor: "Generate STEMI scenario following our protocols"

AI: [reads loaded protocols]
"Creating STEMI scenario:
- 12-lead within 10min (per your protocol)
- Aspirin 324mg (per your protocol)
- Transport to PCI center (per your protocol)
- No nitro if inferior STEMI with RV involvement (per your protocol)

Scenario ready for review."
```

**Features:**
- Protocol parsing (PDF, Word, text formats)
- Structured protocol database (AI extracts key elements)
- Comparison engine (scenario grading vs protocol requirements)
- Conflict resolution workflow (instructor reviews flagged items)
- Protocol version tracking (update notifications)

**Use Cases:**
- QA: "Validate all cardiac scenarios against updated protocols"
- Creation: "Generate trauma scenario matching our 2025 protocols"
- Training: "Show students protocol-based rationale for interventions"
- Compliance: "Generate protocol compliance report for scenarios"

**Grading Integration:**
- Scenarios graded against local protocols (not generic NREMT)
- Deviations flagged in debrief
- "Your agency protocol requires X within Y minutes"

**Multi-Level Support (CRITICAL):**
- **Protocols must support EMR, EMT, and Paramedic scope:**
  - EMR protocols: Basic interventions, recognition, when to call for help
  - EMT protocols: BLS airway, assisted medications, CPR/AED
  - Paramedic protocols: Full scope including advanced airway, medications, electrical therapy
- **Validation scales per certification:**
  - EMR graded on EMR-appropriate interventions from protocol
  - EMT graded on EMT-appropriate interventions
  - Paramedic graded on full protocol compliance
- **Scope recognition graded positively:**
  - EMR recognizes need for ALS → positive points
  - EMT recognizes limitation → positive points
- **Scenario generation:**
  - "Generate EMR-level cardiac arrest scenario" → CPR + AED focus
  - "Generate EMT-level respiratory scenario" → BLS airway + O2 + positioning
  - "Generate Paramedic STEMI scenario" → Full ALS protocol
- **Protocol parsing must identify scope requirements:**
  - Extract which interventions are BLS vs ALS
  - Flag scope-specific timing requirements
  - Identify when protocols specify "ALS required"

**Status:** Priority 1 - v1.7.0

### 2. Timing File Generator ⭐ DESIGNED & READY

**Status:** Design Complete - Ready for Implementation  
**Description:** Generate custom timing standards for different operational environments.

**Purpose:**
Allow instructors to create timing profiles without manually editing JSON files:
- Operational environments (urban vs rural)
- Training emphasis (slower for teaching vs realistic for testing)
- Provider level (ALS vs BLS)
- Agency-specific standards

**Implementation:**

**Global Timing Profile:**
```
Instructor: "Generate timing standards for rural Minnesota EMS"

AI: "I'll create a rural EMS timing profile. Questions:
1. Distance to nearest hospital? (affects scene time)
2. Average backup arrival? (affects resource expectations)
3. Training focus or realistic testing?

Or use standard rural defaults?"

Instructor: "Standard rural defaults"

AI: [generates timing_standards.json]

"Created rural EMS timing profile:
- Scene time: 15-20min acceptable (vs 10-15 urban)
- Backup arrival: 10-20min (vs 3-5 urban)  
- Assessment times: Standard
- IV attempts: Standard
- Transport prep: Extended for weather/distance

Save as: assets/timing_standards.json

All scenarios will use these timing standards."
```

**Scenario-Specific Timing:**
```
Instructor: "Add slow IV timing to this scenario for training"

AI: "Added custom timing to scenario:
- IV prep: 2min (vs 1-1.5min baseline)
- IV attempt: 1.5min (vs 30-60s baseline)
- Focus: Technique over speed
- No time penalties in Easy mode

This scenario uses custom timing; others use global standards."
```

**Timing Profile Types:**

**Urban Profile:**
- Faster scene times (closer hospitals)
- Quicker backup (3-5min)
- Higher tempo expectations
- On-scene max: 10-12min

**Rural Profile:**
- Longer acceptable scene times (distant hospitals)
- Delayed backup (10-20min)
- Self-sufficient care emphasis
- On-scene max: 15-20min

**Training Profile:**
- All interventions +50% time
- Focus on quality over speed
- No time pressure penalties
- Detailed debrief on technique

**Testing/Realistic Profile:**
- Baseline times (no modification)
- Time penalties active
- Monica mode hard limits enforced
- Prepares for field reality

**Validation & Safety:**
- Minimum times enforced (CPR start ≥5s, IV attempt ≥20s)
- Maximum times enforced (CPR start ≤60s, defib ≤120s)
- AI warns about unrealistic or dangerous settings
- Suggests appropriate times if invalid

**File Priority:**
1. Scenario `custom_timing` block (highest priority)
2. Global `assets/timing_standards.json` (if present)
3. Core baseline times (always available fallback)

**Status:** Priority 1 - v1.7.0

## 🎨 Priority 2 Features (Should-Have)

### 4. Equipment Timing Delays

**Description:** Realistic setup and calibration times for medical equipment.

**LUCAS Device:**
- Setup time: 30-45 seconds (verbalized)
- Student must state: "Partner, position LUCAS device"
- Grading check: Did student account for setup delay?
- CPR must continue during setup (delegated to partner)

**Capnography (EtCO₂):**
- Monitor activation: 15 seconds
- Calibration time: 10-15 seconds  
- Student must verbalize: "Enable capnography on monitor"
- Hidden grading: Did student activate early enough?
- Penalty if not activated before needed

**12-Lead ECG:**
- Electrode placement: 20-30 seconds
- Acquisition time: 15-20 seconds
- Total time: ~45 seconds minimum

**IV Pump Programming:**
- Setup time: 15-30 seconds
- Student must verbalize dose/rate

**Ventilator Setup:**
- Assembly: 60-90 seconds
- Settings verification: 15-30 seconds
- Total: ~2 minutes minimum

**Implementation:**
- Add to Core timing standards
- Scenario flag: `equipment_timing_enabled: true`
- Hidden grading criteria
- Debrief feedback

**Status:** Priority 2 - v1.7.0

### 5. Multi-Agency Dynamics

**Description:** Add Fire, Police, and First Responder resources to scenarios.

**Fire Department:**
- Extrication ("Vehicle stable, 10 minutes to extrication")
- Scene safety (hazmat, structural)
- Manpower (lift assists, CPR)
- Equipment (ladders, tools, lighting)

**Police:**
- Scene control (crowd management)
- Traffic control
- Staging requirements (unsafe scenes)
- Evidence preservation

**First Responders:**
- Basic care already initiated
- CPR in progress
- Initial assessment completed
- Handoff report

**Dynamic Arrival:**
- On-scene (already there)
- En route (ETA provided)
- Delayed (must request)
- Student must call for resources

**Grading Integration:**
- Did student request appropriate resources?
- Did student coordinate care effectively?
- Did student stage when scene unsafe?
- Did student utilize available personnel?

**Example:**
```
Scene: MVC with entrapment
Fire: On scene, performing extrication  
Police: En route, ETA 3 minutes
First Responders: Maintaining c-spine

"Fire Captain: 'Vehicle stable, patient trapped. 
We'll have them out in 8-10 minutes. What do you need?'"
```

**Status:** Priority 2 - v1.7.0

## 🛠️ Technical Considerations

### Protocol Loading Implementation

**Supported Formats:**
- PDF (extract text with OCR if needed)
- Word documents (.docx)
- Plain text (.txt, .md)
- Structured JSON (if agency provides)

**Parsing Strategy:**
- AI reads document
- Extracts key elements: medications, doses, routes, timing requirements
- Builds structured protocol database
- References during validation/generation

**Storage:**
- `assets/protocols/agency_name_2025.pdf` (original)
- `assets/protocols/agency_name_2025_parsed.json` (extracted data)
- Version tracking for updates

### Timing File Implementation

**File Format:**
```json
{
  "profile_name": "Rural EMS",
  "created": "2025-12-20",
  "description": "Rural Minnesota timing standards",
  
  "assessment": {
    "scene_size_up": 15,
    "primary_assessment": 45,
    "focused_assessment": 90,
    "full_assessment": 240
  },
  
  "scene_time_targets": {
    "on_scene_goal": 900,
    "on_scene_max": 1200
  },
  
  "circulation": {
    "iv_prep": 90,
    "iv_attempt_success": 60,
    "iv_attempt_fail": 120
  }
}
```

**Priority Loading:**
1. Scenario custom_timing block
2. Global assets/timing_standards.json
3. Core baseline times

### Equipment Timing Implementation

**In Core.txt:**
- Equipment timing constants added to baseline times
- Setup state tracking
- Grading checks for proper sequencing
- Hidden grading items

**Timing Penalties:**
- Minor: -2 points for not verbalizing
- Moderate: -5 points for forgetting to activate
- Major: -10 points for critical timing failure

## 🚧 Known Risks & Mitigations

### Risk: Protocol parsing fails for complex formats
**Mitigation:** Start simple, iterate, allow manual correction

### Risk: Timing customization overwhelms instructors
**Mitigation:** Provide templates, make optional, clear documentation

### Risk: Equipment timing feels tedious
**Mitigation:** Realistic but not frustrating, skip in Easy mode

### Risk: Feature creep delays release
**Mitigation:** Stick to Priority 1 & 2 only, defer Priority 3 to v1.8

### Risk: v1.6.3 bugs delay v1.7 development
**Mitigation:** Dedicated testing phase, fix bugs before starting v1.7
